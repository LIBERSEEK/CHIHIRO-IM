# 千寻产品模型

千寻是围绕 IM 关系和真实消息的 AI 工作台：客户理解、协同接待、运营洞察、业务触达、结果跟踪。IM 是工作现场，不是附属聊天窗。

- **消息 / 联系人：** 操作员面对客户会话。
- **工作台：** 操作员给 Agent 下达跨会话任务。
- **Bot：** 在指定客户会话里执行接待策略的运行模式，不是单独产品。

产品闭环：消息 → 客户与需求线索 → 业务任务 → 草稿或授权执行 → 真实发送结果 → 回复/跟进 → 运营评估。

工程、目录、契约和阶段见 [development.md](development.md)。交互约定见 [iteration.md](iteration.md)。

## 1. 边界与当前工作

默认入口 `/` 已是统一前端：QQ 登录、多账号、消息、联系人、工作台。当前产品工作是 **Bot** 和 **Agent**：

- **Bot：** 在指定客户会话里按策略接待（人工 / 辅助 / 审核 / 自动）。
- **Agent：** 操作员在工作台下达跨会话任务，经同一套工具和发送出口落地。

二者不能互扮。发给客户 ≠ 问助手；Bot 不是常驻自动回复进程。

首期仍是 Docker 自托管、QQ 优先、单操作员多账号。开发机和外部 NapCat 保留。团队协作、云、多平台完整 IM 后置。AstrBot 能接某平台 Bot 接口，不表示该平台已有完整个人号 IM。

营销获客、大规模群发、画像评分、多群情报报告后置，等策略、草稿和统一发送出口可用。

## 2. 工作台

一套前端，多路客户端。交互对标 QQ 桌面，而不是 AstrBot 运维台。

```text
┌──────┬────────────┬─────────────────────┐
│ 左栏  │ 列表        │ 右侧                 │
│ 账号  │ 消息        │ 客户会话             │
│ icon │ 联系人      │ 或 Agent 任务        │
│      │ 工作台      │                     │
│  +   │            │ 会话级接待模式（辅）  │
└──────┴────────────┴─────────────────────┘
   点 icon = 切换当前客户端账号
   中间结构不变，只换数据源
```

- 左栏：每个已登录账号一枚 icon（客户端角标、在线、未读、Bot 状态）。`+` 先选客户端类型，再登录。
- 消息、联系人展示客户会话；工作台展示操作员与 Agent。任务、待审、线索、报告是结构化对象，不伪装成聊天记录。
- 跨账号任务展示作用账号范围，不随左栏当前账号悄悄改执行目标。
- AstrBot Dashboard 只作高级设置；常用的知识范围、接待角色、活动限制进入千寻表单。

NapCat / NTQQ 是协议基座，不是给人看的客户端。用户不要自己执行 `QQ --no-sandbox`。

### 添加账号

下拉选项对齐 AstrBot 官方消息平台（社区适配器后置）。只有 QQ/NapCat 才拉起 NTQQ。

| 客户端 | 登录形态 | Runtime |
|---|---|---|
| QQ / OneBot v11（NapCat） | 工作台内二维码 / 快速登录 | spawn NTQQ `--no-sandbox` |
| Telegram | Bot Token | 适配器，不拉 QQ |
| 飞书 / 钉钉 / 企微 | 开放平台凭证 | 同上 |
| Discord / Slack / LINE / KOOK 等 | 各平台 token | 同上 |
| 微信公众号 | 公众号配置 | 同上 |

QQ 对用户：打开千寻 → `+` 选 QQ → 后台拉起 NTQQ → 未登录展示二维码 → 扫码成功后 icon 进入共用 IM → 后端未退出则下次点 icon 直接看会话。

第一版多账号：工作台账号列表；已登录号快速登录（后端未退出保持会话）；切换由千寻拉起/切换 Shell。真·同时在线多个号后置（优先 Linux / 独立数据目录）。同号不能同时开原生 QQ 和 NapCat。

## 3. 人、助手、Bot

三个角色同时在场，不能互扮。

```text
客户消息 ──► 会话
              ├─ 人直接回     → 发给客户
              ├─ 人问助手     → 内部通道，不进客户历史
              └─ 策略触发     → 候选草稿 → 审批或自动 → 统一发送出口
操作员任务 ──► 工作台 Agent  → 同一套工具与发送出口
```

每个会话独立模式：

| 模式 | AI | 人 |
|---|---|---|
| 人工 | 不主动插嘴 | 自己聊 |
| 辅助 | 操作员调用才分析或给建议 | 决定发不发 |
| 审核 | 触发后出候选，等确认 | 采用 / 改 / 重生成 / 接管 |
| 自动 | 只在预先划定的业务、时段、动作里执行 | 越界进待处理 |

会话输入框右上角机器人打开策略面板。托管后，输入框上方展示工作状态、引用依据、工具摘要、候选回复和接管入口。**保留正常输入，不用不可编辑的托管条替换整个输入区。**

硬规则：

- 「发给客户」和「问助手」是两个动作。
- 操作员内部指示走独立通道，不伪装成客户消息。
- 同会话串行；连续短消息合并成一个回复窗口。
- 新消息、人工开口、人工发信、策略变更会更新会话版本；待发草稿绑定生成时版本，发送前再校验。
- 已提交到平台的消息不能保证取消。界面区分排队、已提交、未知。
- 候选可以是简答、补问或转人工，不只是同义改写。草稿标明针对哪条消息、用了哪些依据、是否因新消息过期。

## 4. 四类现场工作

这些是操作员在 IM 里要完成的事。千寻提供账号、消息、策略、草稿、发送出口和可引用的业务上下文；规划、检索、写作走 Agent 工具与工作流，不另做一套独立 CRM 引擎。

### 4.1 客户理解

在选定账号、群、时间范围内采集消息。建立客户身份、群成员关系和证据引用；按业务知识提取兴趣、明确需求、询价、采购时间、预算（仅有明确依据时）、异议、跟进阶段。

事实、人工标签、模型推断分开存。推断带原文引用、时间、模型/规则版本和可信程度，可改、可过期、可刷新。没有证据就输出未知。LLM 自评置信度不是校准后的购买概率。

工作流：选范围 → 识别候选 → 看证据 → 建线索 → 确定联系路径 → 起草 → 跟进。主动加好友是独立闸门：第一期支持手动添加/待办和接受申请，不以未验证的主动加好友为闭环前提。

群聊文本是分析资料，不是操作员指令。共享画像时，原始消息和检索仍按工作空间、账号、群范围控制。

### 4.2 逐人沟通

Agent 出受众建议、个性化内容和任务计划；持久化执行器发信。一次活动保存受众快照、排除名单、账号、内容版本、时间窗、配额、停止条件、授权范围和每人执行记录。

可整体确认一个明确范围，不要求机械逐条审批；改受众、账号或内容则重新形成可审查版本。支持暂停、取消未执行项、恢复、去重、失败分类和结果导出。拒绝继续联系或正在人工洽谈的对象，从后续任务排除。

群成员枚举不等于有私聊通道。好友、已建立临时会话、未知联系路径分别标记。平台接受请求不等于已读，更不等于成交。对象回复后，暂停其未发的活动消息，转入会话接待。

### 4.3 群情报

增量采集 → 过滤 → 去重和话题聚合 → 分组摘要 → 跨群综合 → 带引用的报告。按消息序号和来源维护游标、覆盖范围与缺口；未采集到的时间段不能当成没有讨论。引用必须回到原始消息。

群情报报告已接入本地过滤组件：默认分析模式保留问题、需求、反馈和含义不明的短句，排除明显客套与噪声；可选择通知模式及按群关键词策略。过滤和重复合并不删除原文，报告保存判定原因、规则版本与全部来源。实现及 API 见 [群聊分析过滤组件](message-filter.md)。

报告可转为选题、提纲、文案草稿；引用群聊素材时提供去身份化。外部发布是另一个执行动作，不与「生成报告」合并。

### 4.4 会话客服

第 3 节的模式就是客服现场。知识范围、工作时段、动作权限写在会话策略里。无依据的问题转人工。人工发言或新消息使旧草稿失效。

## 5. 发送与授权（产品原则）

所有 AI 发信、活动发信、候选确认走同一个服务端出口。人工发信至少立刻归并进消息流并触发接管。

「已发送」只表示平台接受请求，不编造已送达/已读。重复确认不能连发。超时是未知，不是成功。未授权的动作直接拒绝，不用假成功安抚 Agent。授权和停止规则写在服务端，不依赖模型自行判断该不该执行。

外部 Agent 可以观察账号、会话、历史，但发信走同一套闸门。见 [mcp.md](mcp.md)。

## 6. 各层在产品里的位置

| 层 | 用户能感到的 | 不承担 |
|---|---|---|
| Stapxs | QQ 风格会话、联系人、历史、输入 | Agent 推理、任务、业务权限 |
| NapCat | 登录、收发、好友/群/历史背后的 QQ 能力 | 画像、营销、Agent 规划 |
| AstrBot | 模型、知识库、工作台对话、插件 | 客户真相、活动状态、人工审核、统一发信授权 |
| 千寻 | 账号与现场、策略与草稿、可追踪结果 | 重写上述成熟能力 |

采集只要启用就不依赖浏览器开着，也不依赖某个 Bot 开关。关掉一个页面或一个会话的托管，不能停掉其他任务仍需要的 Agent。浏览器关了，部署中的后台继续跑；主机停机后由持久化执行器在重启后恢复。

## 功能删剪（2026-10-11）

添加账号保留 QQ；抖音、小红书、Bilibili 的账号登录与评论获客模块、任务预览、Agent 营销模式和对应 MCP 工具已移除。本地历史账号和素材数据保留，已停用的平台账号不再出现在工作台。QQ、Bot、Agent、客户资料和群聊分析继续保留。
